## 1-1. 프로젝트 목적

> 전국 자동차 등록 현황을 중심으로 지역별 **고령화 · 고령운전자 교통사고 · 장래인구 · 운전면허/면허반납 정책** 데이터를 통합하여, 현재와 미래의 지역 자동차·교통환경을 조회·비교하고 정부·지자체의 정책 의사결정을 지원하는 데이터 분석 시스템 구축

---

## 1-2. 프로젝트 배경

- 자동차 등록·인구·고령화·교통사고·운전면허·정책 데이터가 **서로 다른 기관·시스템에 분산** → 지역 단위 종합 분석에 별도 수집·가공 작업 필요
- 현재 현황뿐 아니라 **장래인구 전망**까지 함께 확인해 향후 정책 수요를 선제적으로 판단할 필요
- 공공데이터·공식 통계를 수집·정제해 MySQL에 저장하고, **Python(Streamlit) 기반 통합 대시보드·지역 비교·미래전망·보고서** 기능 제공
- 향후 **API 연동**을 통한 기관 시스템 확장까지 고려한 구조로 설계

## 2. 이해관계자

**내부**
- 기획/요구사항 담당 — 시장조사·Pain Point·요구사항 우선순위 정의
- 데이터 수집·분석 담당 — 원천 데이터 조사·수집·전처리
- DB/개발 담당 — MySQL·ERD 설계, 조회 쿼리·분석 로직 구현
- UI/API 담당 — Streamlit 대시보드·시각화·보고서, 향후 API 구조 설계

**사용자 (핵심)**
- 지자체 교통정책 담당자 · 교통안전 담당자 · 스마트도시/데이터 담당자 · 중앙정부·공공기관 담당자

**외부**
- 공공데이터 제공기관 (공공데이터포털 / KOSIS / TAAS / 공식기관)

## 3-2. RF-1.0 자동차 등록 현황 조회·시각화

- **RF-1.1** 공공데이터 등에서 지역·연도·차종·신규/말소 등록 등 원천 데이터 수집
- **RF-1.2** 지역·연도·차종·신규/말소 조건별 등록 현황 조회
- **RF-1.3** 조건별 등록대수 및 증감 현황 표 비교
- **RF-1.4** 지역·연도·차종별 차이를 그래프로 시각화

---

## 3-3. RF-2.0 고령화·미래전망·지역 종합분석

- **RF-2.1** 지역별 총인구, 65세 이상 인구, 고령화율, 고령운전자 수, 면허소지자 수 수집
- **RF-2.2** KOSIS 등에서 2030·2035 장래인구·고령화율 수집(현재 데이터와 동일 기준 관리)
- **RF-2.3** 지역 선택 시 등록·고령화·사고·미래전망을 한 화면에서 통합 조회
- **RF-2.4** 선택 지역 지표를 전국 평균/타 지역과 비교
- **RF-2.5** 현재↔2035 고령화 변화, 인구 대비 등록·사고 수준을 표·그래프로 제공 (미래 사고건수는 단순 예측하지 않음)

---

## 3-4. RF-3.0 지역별 고령운전자 교통사고 분석

- **RF-3.1** TAAS 등에서 지역·연도별 고령운전자 사고건수·유형·사상자·심각도 수집
- **RF-3.2** 지역·연도 선택별 사고 발생 현황 조회
- **RF-3.3** 사고유형(차대차/차대사람/차량단독 등)·심각도(사망/부상 등) 조건 조회·비교
- **RF-3.4** 등록대수·고령운전자 수 대비 상대적 사고 수준과 연도별 추이 시각화

---

## 3-5. RF-4.0 운전면허 자진반납·정책 분석

- **RF-4.1** 지역별 자진반납 인원·반납률 및 지원정책(정책명/시행일/대상연령/지원금) 구축
- **RF-4.2** 지역·연도별 자진반납 인원·반납률 조회 및 지역 간 비교
- **RF-4.3** 정책 시행 시점 기준 전후 사고건수·사고율 변화 비교

## 4. 비기능적 요구사항 (NFR)

| 구분 | 핵심 내용 |
|---|---|
| **성능** | 일반 조회 3초 이내 응답, 통합분석·보고서는 처리상태 표시 + 합리적 시간 내 제공 |
| **정확성·신뢰성** | DB 저장값과 조회·분석 결과 일치, 중복·누락 방지, 출처·기준연도·관측값/추계값 구분 표시 |
| **사용성** | 별도 분석 지식 없이 지역·연도·차종·사고유형 등으로 직관적 조회, 그래프에 제목·단위·범례·기준연도 명시 |
| **보안** | 외부 API 키·인증정보 GitHub 비노출, MySQL 접속정보 하드코딩 금지(환경변수/Secrets) |
| **유지보수성·확장성** | 코드·SQL·ERD·문서 역할별 관리 및 GitHub 형상관리, 신규 데이터·API 확장 시 기존 구조 최소 변경 |

## 5. 제약사항 및 대응방안

| 구분 | 제약 내용 | 대응 방안 |
|---|---|---|
| 데이터 | 제공 항목·기간·갱신주기가 제공기관 정책에 의존 | 조사 단계에서 항목·기준연도 확인 후 확보 가능 범위로 기준 확정 |
| 데이터 품질 | 결측값·중복값·지역명/연도 형식 불일치 가능 | 수집 후 검증 및 지역·연도 기준 표준화 |
| 정책 데이터 | 여러 지자체·기관 자료에 분산 | 공식 자료 우선 사용, 정책 조건·기준연도 별도 관리 |
| 미래 전망 | 장래인구는 추계값, 고령화만으로 미래 사고 직접 예측 불가 | 관측값/추계값 구분 표시, 사고건수 단정 대신 변화 가능성 중심 제시 |
| 보안 | API 키·DB 비밀번호 노출 위험 | 환경변수/Secrets, .gitignore, 민감정보 커밋 금지 |
| 일정 | 다수 데이터·기능 동시 구현 시 범위 과다 | 등록·고령화/미래·사고·종합분석을 MVP 핵심으로, API·FAQ는 단계적 적용 |
| 분석 해석 | 정책 전후 변화를 정책만의 효과로 단정 불가 | 상관관계는 제공하되 인과관계 단정 표현 제한, 분석 한계 명시 |

## 6. 기대 효과

**긍정적 효과**
- 등록·고령화·사고·면허반납·미래전망을 지역 기준으로 통합 조회 → 여러 기관 데이터 탐색 시간 절감
- 현재 현황 + 2035년 전망을 함께 확인하고 보고서 생성, 향후 API로 기관 내부 시스템 활용 가능

**한계 및 대응**
- 데이터 제공범위·정책 정보·장래 추계의 한계로 일부 지역 비교/미래 해석이 제한될 수 있음
- → 출처·기준연도·추계 여부 명시 및 분석 한계를 함께 안내
