## ⚙️ 2. 데이터 전처리 파이프라인

```
원본 Excel/CSV
    ↓ 헤더 구조 확인
    ↓ 결측치·병합 셀 처리
    ↓ 합계·불필요 행 제거
    ↓ 컬럼명·문자열 표준화
    ↓ Wide → Long 변환
    ↓ 연도·지역·연령·시간대 추출
    ↓ 데이터 타입 변환
    ↓ Pivot/파생 구조 생성
    ↓ 전처리 결과 검증
```

**공통 전처리 기준**: 지역 · 연도 · 연령 · 시간대

---

## ⚙️ 전처리 실전 사례

| 문제 | 해결 |
|---|---|
| 병합 셀 → `NaN` | `ffill()`로 상위 값 복원 |
| 연도가 컬럼으로 흩어진 Wide 구조 | `melt()`로 Long Format 변환 |
| 기관별 CSV 인코딩 상이 | `utf-8-sig`/`cp949`/`utf-8`/`euc-kr` 순차 처리 |
| 합계·소계 행 중복 집계 | 사전 필터링으로 제거 |

> TAAS 연령대별 사고 데이터의 경우 `ffill()` → Long 변환 → `pivot_table()`로 **accidents / deaths / injuries** 3개 지표로 재구성했습니다.

## 🗄️ 3. DB 설계 — SQLite → MySQL 전환

| 구분 | 초기 (SQLite) | 전환 후 (MySQL) |
|---|---|---|
| 목적 | 빠른 기능 구현·테스트 | 분석 데이터 통합 관리 |
| 연결 | `.db` 파일 직접 연결 | SQLAlchemy + PyMySQL |
| 관리 단위 | 파일 단위 | 테이블 단위 통합 관리 |
| 확장성 | 소규모 프로토타입용 | 데이터·테이블 확장에 유리 |

> 데이터·분석 테이블이 늘어나고 여러 페이지에서 같은 데이터를 조회하게 되면서 **체계적 관리를 위해 MySQL로 전환**했습니다.

---

## 🗄️ DB 적재 구조

```
전처리 함수 ↔ 테이블명 매핑
        ↓
테이블 생성 확인 (CREATE TABLE IF NOT EXISTS)
        ↓
기존 데이터 초기화 (TRUNCATE)
        ↓
DataFrame.to_sql(if_exists="append", chunksize=1000)
        ↓
적재 결과 검증 (행/컬럼 수, 오류 로그)
```

- 대표 테이블: `accident_age`, `accident_region`, `driver_age_accident`, `education_reservation`, `old_driver_policy` 등
- **전처리 함수 ↔ 테이블 매핑 구조**라서 새 데이터 추가 시 매핑만 추가하면 재사용 가능

## 🚨 교통사고 심각도 분석

사고건수만이 아니라 **사망자·부상자**를 함께 봐야 진짜 위험도가 보입니다.

- 사고건수 → 발생 규모
- 사망자 수 → 피해 심각성
- **사고 100건당 사망자** → 집단 간 치명도 비교
- **사고 1건당 부상자** → 평균 인적 피해 비교

→ **사고가 많은 지역**과 **사고가 나면 피해가 큰 지역**을 구분해서 볼 수 있습니다.

## 🔮 5. 미래 전망 분석 — 두 가지 방식

### ① Linear Trend
과거 연도별 추세를 직선으로 연장해 미래 값 추정
- 적용: 인구·자동차·면허·사고 전반의 추세

### ② Proxy Growth Scenario
직접 데이터가 부족할 때, 관련성 높은 지표의 성장률을 대리(Proxy)로 활용
- 적용: 고령인구 증가율 → 고령운전자 관련 미래 시나리오

---

## 🔮 왜 ARIMA·Prophet·LSTM이 아니었나

| 기법 | 필요 조건 | SAFE 데이터 |
|---|---|---|
| ARIMA | 충분한 시계열 관측치 | ❌ 2021~2025, 짧은 연 단위 |
| Prophet | 장기 일·월 단위 + 계절성 | ❌ 계절성 데이터 부족 |
| LSTM | 대량 학습 데이터 | ❌ 데이터·튜닝 리소스 부족 |
| **Linear Trend / Proxy** | 짧은 시계열에서도 해석 가능 | ✅ 적용 |

> 정확한 예측값 단정이 아니라, **"현재 추세가 지속된다면"의 변화 방향 전망치**로 활용합니다.

---

## 🎯 정책 대응 우선순위 분석

```
현재 사고 수준 + 미래 사고 변화 + 고령인구 변화
                    ↓
        정책 대응 우선순위 지표
```

- 단순히 사고건수가 높은 지역만 보지 않고
- **현재 위험 + 미래 증가 가능성**을 함께 고려해
- 선제적 정책 검토가 필요한 지역을 탐색하는 **참고 지표**로 제공

## 🔧 주요 트러블슈팅

| 문제 | 해결 |
|---|---|
| Excel 병합 셀 → NaN | `ffill()` 복원 |

| 재적재 시 데이터 중복 | `TRUNCATE` 후 적재 |
| 짧은 시계열로 예측 어려움 | Linear Trend / Proxy 적용 |
| SQLite 관리 한계 | MySQL 전환 |
